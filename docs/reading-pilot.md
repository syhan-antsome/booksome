# 첫 독서 경험 검증

목표는 ‘읽고 지나간 책과 문장이 나에게 남는가’를 실제 행동으로 확인하는 것입니다. 기능 완성과 사용자 만족은 별도로 판단합니다.

## 이번에 연결한 흐름

공개 웹 → 첫 책 찾아보기 → 제목·저자·ISBN 검색 → 로그인/가입 → 서재 등록 → 첫 기록 → 저장 확인 → 재방문 → 완독 → ‘이 책에서 내가 남긴 것’.

- 책 검색은 로그인 전에도 가능합니다. 저장할 때 로그인하며 찾던 책으로 돌아옵니다.
- 전체 페이지 입력은 선택입니다. 글 기록은 기본적으로 비공개입니다.
- 완독 회고는 실제 사용자가 작성한 기록을 모읍니다. AI가 내용을 만들어내거나 공개 범위를 변경하지 않습니다.
- `/app/`은 모바일과 같은 Expo 화면을 브라우저로 제공합니다. 설치 없이 핵심 경험을 검증할 수 있습니다.

## 사용자 확인 방법

책은 읽지만 기록이 흩어져 아쉬운 독자 5~8명을 우선 모집합니다. 다음 행동을 자신의 책으로 해보도록 요청하되 화면을 조작하는 방법을 먼저 설명하지 않습니다.

1. 읽는 책을 찾아 서재에 담고, 마음에 남은 생각을 남깁니다.
2. 다음 독서 때 다시 방문해 이전 기록을 찾고 이어서 기록합니다.
3. 완독한 책을 표시하고, 자신이 남긴 기록을 다시 봅니다.

첫 기록까지 걸린 시간, 막힌 지점, 도움을 요청한 이유를 관찰합니다. 이후 1~2주 동안 독서 기회가 있었는지와 실제 재사용 여부를 함께 확인합니다. 재방문하지 않았다면 이유를 묻습니다. ‘예쁜가요?’와 ‘다시 사용했나요?’를 구분합니다.

소수의 결과를 시장 전체의 선호나 정량 전환율로 일반화하지 않습니다. 이 단계에서는 공통으로 막히는 지점과 다시 쓸 이유를 찾습니다. 사용자 기록 원문을 동의 없이 연구 자료로 수집하지 않습니다.

## 개발 검증

- 루트: `npm run typecheck`, `npm run test:reading`, `npm run build:reader`
- 공개 웹: `npm run typecheck`, `npm run lint`, `npm run build`
- 전체 흐름은 `/app/`에서 확인합니다. 운영 데이터 생성 없이 검증하려면 Next.js의 `BOOKSOME_API_INTERNAL_URL`을 격리된 테스트 API로 설정합니다.
- 네이티브 카메라와 실제 기기 키보드, SMTP 이메일 및 실서비스 통합은 별도 기기·환경 검증이 필요합니다.
