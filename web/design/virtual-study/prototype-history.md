## 목적과 현재 범위

사용자가 고른 책이 입체 공간에 쌓이고, 책상과 서재를 자신의 취향으로 꾸미는 경험의 가능성을 확인한다. [승인된 첫 시안](concept.png)을 바탕으로 실제 Three.js 메시·재질·조명을 구현했다. 방 전체를 하나의 평면 이미지로 붙인 화면이 아니다. `/study`만 엔진을 지연 로딩하므로 기존 공개 포털과 개인 독서 화면에 Three.js를 추가하지 않는다.

회전·확대, 전체/책장/책상 시점 이동, 화면 이동 모드, 책 클릭 및 키보드로 접근할 수 있는 책 목록, 식물·러그 표시, 햇빛 강도·소품 색 변경, 빈 서재와 시안 보기 전환을 제공한다. 꾸미기 설정만 이 브라우저의 `booksome-study-settings-v1`에 저장한다. 계정별 공간 저장이나 가구를 직접 끌어 옮기는 편집기는 아직 없다.

‘둘러보기’는 Trackball 방식의 자유 회전이다. 마우스·펜 또는 한 손가락 드래그로 상하좌우 어느 방향으로든 계속 돌릴 수 있다. 위·아래 극점을 넘어 뒤집힌 방향까지 회전하며, 확대 상태에서도 동일하게 동작한다. 각도 제한이나 확대 중 세로 드래그를 높이 이동으로 바꾸는 동작은 없다. ‘화면 이동’은 화면을 직접 끌어 상하좌우로 옮기는 방식이다. 마우스 오른쪽 드래그와 캔버스에 초점을 둔 방향키도 이동을 지원한다. 두 손가락으로 확대와 이동을 함께 한다. 조작 버튼 옆의 ‘처음 구도’를 누르면 새로고침 없이 회전·위치·확대를 원래 구도로 복원한다. 책, 꾸미기 설정, 현재 조작 모드는 유지한다. 하단 ‘전체’ 시점도 같은 카메라 구도로 이동한다.

처음은 시안 도서가 있는 상태이며 화면에 시안임을 표시한다. 로그인하면 ‘책 추가 → 내 책 불러오기’로 기존 `/api/reader/reading-life/books`의 실제 개인 서재를 읽는다. 책장 책의 첫 클릭은 책 길이의 2/3만큼 꺼내고, 다른 책장 책을 클릭하면 이전 책은 돌아가고 새 책이 나온다. 책상 위 펼친 책만 제자리에서 420ms 동안 따뜻한 빛과 작은 별 모양으로 한 번 반짝인 후 상세로 바로 이동한다. 꺼낸 책을 다시 클릭하면 실제 책은 기존 `/library/[id]`의 정보·기록으로, 시안 책은 시안 표시가 있는 `/study/books/[id]` 상세 페이지로 이동한다. 운영 DB를 직접 읽거나 수정하지 않는다. 실제 계정 책 불러오기는 이번 브라우저가 로그아웃 상태이므로 로그인한 통합 흐름의 추가 확인이 필요하다.

첫 클릭은 팝업을 열지 않으므로 곧바로 다른 책을 고를 수 있다. 비모달 선택 안내의 ‘상세 보기’ 링크도 같은 상세로 이동하며, 책 목록은 키보드로 책을 고르는 대안이다. 안내의 ‘책 다시 꽂기’, 빈 공간 클릭, Escape로 책을 돌려놓을 수 있다. 이동은 320ms의 재지정 가능한 보간으로 진행하고 모션 감소 설정에서는 즉시 위치를 바꾼다. 가구와 벽을 포함한 가장 앞의 보이는 표면으로 클릭을 판정해, 가려진 책이 벽을 통과해 선택되지 않는다. 서재 시점 초기화는 선택한 책을 유지하며, 도서 목록 교체와 장면 해제는 선택·대기 애니메이션을 정리한다.

현재 API의 책 상태는 `reading / finished`다. `want`는 시안 표현에만 쓰며 실제 읽고 싶은 책/읽어야 하는 책 등록 기능이 추가됐다는 뜻이 아니다. 입체 전시는 첫 96권을 대상으로 빈 칸에 배치하며, 책 두께와 가로 쌓기에 따라 그보다 먼저 공간이 찰 수 있다. 나머지를 포함한 모든 책은 목록에서 접근할 수 있다. 등록량에 따른 책장 증축은 후속 구현 사항이다.

- `src/lib/study/books.ts`: 정확한 제목/저자로 만든 책등과 표지, 실제 표지의 가능한 경우 WebGL 로딩. 원본 책등 디자인을 재현한다고 주장하지 않는다.

- `src/lib/study/grounding.ts`: 기울기와 상위 오브젝트 변환을 반영한 월드 경계의 최저점을 바닥 또는 러그 표면에 맞춘다.
- `src/lib/study/desk-collision.ts`: 책상 소품의 높이·가로/깊이 경계상자로 충돌을 검사하고 책상 안에서 가장 가까운 빈 위치로 밀어낸다.

렌더링은 상호작용·카메라 이동·재질 변경과 아래에 기록한 짧은 수첩 안내 효과 중에 갱신하고, 효과 사이에는 멈춘다. 탭이 숨겨지면 중단한다. 모바일 DPR은 1.25로 제한하며 800px 미만은 후처리를 생략한다. 해제 시 기하·재질·텍스처·그림자·이벤트·렌더러 컨텍스트를 정리한다. 그래픽 미지원/에셋 실패 시 재시도와 기존 서재 링크를 제공한다.

## 시안 대조와 한계

첫 시안의 1536×1024와 같은 크기 및 375px 모바일 화면에서 브라우저로 확인한다. 대조 기준은 원목 모듈 책장·왼쪽 창문·앞쪽 책상/의자·오른쪽 식물/오토만의 배치, 따뜻한 중립 바탕과 코랄, 헤더/하단 선택 UI, 원목·직물 재질, 카메라 시점과 실제 조작이다.

첫 구현에 대한 사용자 검토 후 의자와 담요를 별도 모델로 다시 만들었다. 담요는 팔걸이를 따라 접힌 두께 있는 메시이며 끝의 술 장식도 실제 기하다. 뒤쪽 책장은 둥근 연속 프레임과 깊은 왼쪽 모듈로 바꿨고, 책상은 가는 네 다리 대신 두꺼운 원목 측판을 사용했다. 원목 결·마루·부클레·러그·담요 재질을 구분하고, 책 배치와 식물·액자 공간을 분리했다. 창가에 식물이 보이도록 창턱과 책상 높이도 조정했다.

카메라 이동 비활성화가 최대 확대에서 위쪽 책을 볼 수 없던 원인이었다. 이동을 활성화하고 모드 버튼, 방향키, 두 손가락 이동, 이동 범위 제한을 추가했다. 바닥 화분과 액자는 서로 떨어뜨렸으며 실제 월드 좌표의 바운딩 박스 중첩도 검사한다.

추가 사용자 검토에서 기본 ‘둘러보기’의 세로 드래그가 각도 제한에서 멈추는 문제를 재현했다. 확대 중 세로 드래그를 높이 이동으로 바꾼 중간 구현 이후, 사용자가 어느 방향으로든 계속 회전하는 방식을 선택했다. 최종 구현은 OrbitControls를 TrackballControls로 교체하고 중간 높이 이동 동작을 제거했다. 드래그가 끝나면 회전도 멈추며, 손을 놓았을 때 자동으로 계속 도는 기능은 아니다. 카메라 프리셋은 뒤집힌 up 벡터도 쿼터니언 보간으로 복원한다. 큰 휠 입력은 항상 양수인 지수 배율로 처리한다.

사진 같은 원본 렌더와 완전히 같지는 않다. 가구의 상대 비율, 식물의 종류와 세부 표현, 책의 색·배치, 사진 같은 간접광에는 차이가 있다. 실제 3D 가구와 조명으로 구성했지만 오프라인 렌더 수준의 전역 조명이나 광선 추적은 적용하지 않았다. 실제 스마트폰 GPU·배터리·프레임률 및 다른 브라우저 확인이 남아 있다. 이 결과를 운영 출시 완료로 취급하지 않는다.

## 검증 명령

루트 `npm run typecheck`, `npm run test:reading`; 웹 `npm run typecheck`, `npm run lint`, `npm run test:portal`, `npm run build`. 브라우저에서는 시점 이동·책 터치·설정 변경과 재방문 유지·빈 상태·로그아웃 시 로그인 링크·모바일 배치를 확인한다. 개인 책 조회 및 원격 표지 이미지의 WebGL CORS 허용 여부는 실제 로그인 계정과 해당 이미지 호스트에서 추가 확인한다.

### 이번 확인 결과

루트 타입 검사 및 독서 테스트 11개, 웹 타입 검사·린트·포털/서재 테스트 28개·프로덕션 빌드가 통과했다. 빌드에는 기존 Expo 웹 리더 내보내기도 포함된다. 새 `/study` 로그인 복귀를 허용하면서 다른 목적지로 허용 범위가 넓어지지 않는 회귀 테스트를 추가했다. 책 꺼내기 테스트는 두 단계 클릭, 이전 책 복귀, 빠른 A→B→A 재선택, 애니메이션 도중 상세 열기, 목록 교체/선택 해제, 모션 감소, 실제/시안 상세 경로를 검증한다.

Codex 인앱 브라우저에서 1536×1024와 375×812를 확인했다. 정상 제목/URL, 의미 있는 첫 화면, 프레임워크 오류 화면 없음, 드래그 회전·전체/책장/책상 이동·책 선택·키보드 접근 가능한 목록 선택, 설정 변경/새로고침 후 유지, 빈 서재에서 책 제거를 확인했다. 유휴 프레임 수가 7→7로 유지되어 정지 상태의 렌더링 중단도 확인했다. 원본 시안과 최신 브라우저 캡처를 이미지로 직접 대조했다.

개발 서버뿐 아니라 별도의 로컬 포트에서 프로덕션 빌드도 열어 데스크톱/모바일 화면을 확인했다. 마지막 개발 서버 로드와 프로덕션 로드 이후 앱 콘솔 경고/오류는 없었다. 로컬 검토 주소는 기존 `http://127.0.0.1:3000/study`로 유지한다.

최대 확대 `zoom=3.600`을 유지한 상태로 데스크톱 드래그에서 카메라 목표 높이가 2.600→3.854, 방향키에서 4.133으로 이동했다. 모바일 폭에서도 드래그로 2.600→5.033으로 이동하고 위쪽 책을 확인했다. 이 검증은 모바일 화면 크기의 브라우저 마우스 입력이며 실물 휴대전화의 멀티터치를 검증했다는 뜻은 아니다. 바닥 화분과 액자의 바운딩 박스 중첩은 `false`다.

자유 회전 구현에서는 1536×1024에서 세로 드래그 6회로 한 바퀴를 넘어 회전했다. 카메라 up.y는 0.315→-0.801→-0.821→0.284→0.999→0.347로 변화해 극점을 넘고 뒤집힌 자세를 지나 다시 원래 방향으로 돌아오는 것을 확인했다. 좌우 반복 드래그의 방위각도 기존 제한을 넘어 2.526→-1.881→-0.132→1.766→-2.754로 계속 변했다. ‘전체’ 복귀 시 up.y=1.000과 기본 확대율을 복원했다. 최대 확대 3.600에서도 자유 회전, 위치 이동으로 최상단 책 보기, 방향키, 책 클릭과 상세 창을 확인했다. 1280×720에서 260px 이동으로 높이가 2.600→3.733으로 변했다. 375×812의 마우스 입력에서도 up.y=-0.342로 극점을 넘어 회전하고 ‘전체’로 정상 복귀했다. 실물 스마트폰 멀티터치는 직접 검증하지 않았다.

실제 로그인 개인 서재, 실물 스마트폰 GPU/배터리·핀치 동작, 다른 브라우저 및 그래픽 미지원 환경은 이번에 직접 검증하지 않았다. 배포·커밋은 하지 않았다.

‘처음 구도’ 버튼은 PC에서 회전으로 뒤집고 위치 이동 및 최대 확대를 한 뒤 검증했다. 확대율 3.600, 목표 높이 1.760, up.y=-0.829에서 버튼 한 번으로 확대율 0.980, 목표 높이 2.000, up.y=1.000, 초기 방위각과 회전 각도로 복귀했다. 시안 책 72권과 조작 모드를 유지했다. 375px 모바일 화면에서도 버튼이 화면 안에 표시되고 책장 시점에서 첫 구도로 복귀하는 것을 확인했다.

책 꺼내기 구현 후에는 실제 캔버스 클릭으로 `demo-47`을 꺼내고, `demo-49`를 골라 첫 책이 돌아가고 한 권만 나온 상태를 확인했다. 나온 책의 두 번째 클릭으로 ‘변신 이야기’ 상세의 URL과 제목을 확인했다. 세워 둔 책의 기울기를 없애고, 각 칸의 실제 높이에 맞춰 책과 가로 쌓기를 배치했다. 전체 시안 메시의 기울어진 책 수와 칸의 X/Y 경계를 넘는 책 수는 모두 0이다. 375px 화면에서는 책 목록 선택→꺼내기→상세 링크를, 800px에서는 안내와 시점 버튼의 겹침이 없음과 ‘책 다시 꽂기’를 확인했다. 시안 상세의 잘못된 ID는 HTTP 404이며 실제 계정 상세의 인증된 통합 흐름은 추가 확인 대상이다.


### 원근 카메라 수정과 확인

원근이 어색하다는 검토 후 정사영을 PerspectiveCamera로 교체했다. 정사영에서는 거리가 달라도 같은 크기로 보이지만, 현재는 가까운 가구와 바닥이 크게, 먼 책장이 작게 보인다. 중심 시야 크기를 유지하도록 화면 비율에 따라 시야각을 맞추고 프리셋의 시점 거리를 32로 통일했다. 화면 이동은 현재 거리·시야각·확대율에서 계산한 가로/세로 시야 크기를 기준으로 한다. Trackball은 자유 회전을 담당하고 휠·가운데 버튼·핀치는 같은 렌즈 확대율 범위를 사용한다. 두 손가락 중심 이동에도 같은 화면 이동 계산을 사용한다.

실제 Three.js 투영 테스트에서 같은 폭의 물체를 거리 10과 20에 배치해 가까운 물체가 두 배 폭으로 보이는 것을 확대율 .65 / .98 / 1.8 / 3.6에서 검증했다. 데스크톱/세로 모바일 비율에서 회전·확대 후 화면 이동량도 실제 투영과 일치한다. Chrome 1507×1191에서 자유 회전으로 up.y=-.975가 되는 뒤집힌 자세를 확인하고, 이동·확대 후 ‘처음 구도’로 up.y=1, zoom=.98, target.y=2를 복원했다. 최대 확대 3.6에서도 250px 이동으로 목표 높이가 2→2.668로 바뀌었다. 캔버스에서 demo-47→demo-49를 선택해 한 권만 나온 상태와 두 번째 클릭의 시안 상세 이동을 확인했다. 375×812에서는 전체 공간 표시·책장 시점·처음 구도 복원을 확인했다. 네이티브 멀티터치는 추가 확인 대상이다.

이번 브라우저의 유일한 콘솔 오류는 설치된 HWP 확장이 html에 data-hwp-extension 속성을 주입하면서 발생하는 React hydration 경고였다. 카메라 변경과 별개이며 경고를 숨기는 코드나 확장 설정 변경은 하지 않았다. 앞선 정사영 검증 수치는 당시 기록으로 보존한다.


### 펼친 책의 단일 클릭

펼친 책만 꺼내기 선택 상태에 들어가지 않는다. 쌓인 책은 책장 책과 같은 두 번 클릭 동작을 사용한다. 클릭한 책만 제자리에서 한 번 밝아지고 별 세 개가 짧게 나타난 뒤 상세로 이동한다. 목록에서 펼친 책을 선택해도 같은 동작을 사용한다. 진행 중 반복 클릭은 효과를 재시작하거나 상세 이동을 중복 호출하지 않는다. 모션 감소 설정이면 효과와 지연 없이 바로 이동한다. 선택 해제·목록 교체·그래픽 중단·장면 해제 시 효과와 대기 이동을 취소하고 원래 재질을 복원한다. 임시 복제 재질은 텍스처를 공유하므로 해제할 때 텍스처는 삭제하지 않는다.

이전 구현에서는 펼친 ‘칼의 노래’와 쌓인 ‘데미안’ 모두 한 번 클릭으로 상세를 열었다. 이후 사용자 검토에 따라 아래처럼 동작을 분리했다. 책장 ‘젊은 베르테르의 슬픔’의 첫 클릭은 상세로 이동하지 않고 한 권만 꺼내진 상태를 유지했다. 반짝임이 최대에 가까운 순간의 화면을 캡처해 책의 위치가 유지되고 주변 가구가 함께 발광하지 않는 것도 확인했다. 웹 타입 검사·린트·기존 테스트 23개·프로덕션 빌드가 통과했다. 실물 휴대전화 터치 및 로그인한 개인 도서의 상세는 이번 변경에서 직접 확인하지 않았다.


### 쌓인 책과 책상 소품 충돌

책상에 쌓인 닫힌 책은 책장 책과 동일하게 첫 클릭→2/3 꺼내기, 다른 책 클릭→이전 책 복귀, 두 번째 클릭→상세 이동으로 동작한다. 펼친 책은 userData.openBook으로 구별한다. 목록 선택에서도 동일한 구별을 사용한다.

스탠드를 앞쪽 왼편, 연필꽂이를 뒤쪽 왼편으로 옮기고 쌓인 책을 책상 뒤쪽 경계 안으로 조금 이동했다. 스탠드·연필꽂이/연필·컵/손잡이·수첩·꽃병/꽃을 각 그룹으로 묶었다. 펼친 책과 수첩의 겹침도 제거하고 수첩 폭을 .76→.70으로 소폭 조정했다.

실제 메시의 월드 경계상자로 책과 소품의 높이 겹침을 검사하고 X/Z에서 최소 0.045의 간격을 둔다. 충돌하는 소품은 기존 위치에서 가장 가까운 빈 자리로 이동하며 다른 소품도 순서대로 밀려난다. 책의 꺼내기/복귀 매 프레임에서도 판정하므로 움직이는 책이 소품을 통과하지 않게 한다. 책상 경계 안에서만 후보 위치를 고른다. 빈 자리가 전혀 없을 때는 오브젝트를 숨기거나 책상 밖으로 보내지 않고 진단에 남긴다. 현재 시안의 초기 상태와 각 쌓인 책의 꺼내기 상태에서는 미해결 충돌이 없다. 장식용 빛 테두리는 물리 경계에서 제외하고, 서로 높이가 다른 책 더미와 지지 가구의 의도된 접촉은 유지한다. 적용 대상은 책상 소품과 아래에 기록한 바닥 소품이며, 방 전체의 중력·낙하·전도 시뮬레이션을 구현한 것은 아니다.

Chrome 1507×1191에서 데미안 첫 클릭 후 URL이 /study에 머물고 반짝임 없이 한 권이 나오는 상태, 소유냐 존재냐로 바꾸면 이전 책이 복귀하고 한 권만 나오는 상태, 다시 클릭하면 demo-2 상세가 열리는 것을 확인했다. 펼친 칼의 노래는 한 번 클릭으로 demo-0 상세를 유지한다. 초기/꺼내기 상태의 deskCollisions=0과 콘솔 오류 없음도 확인했다. 테스트에는 충돌 시 소품 밀기와 책상 경계, 연속 이동 후 겹침 없음과 정지 상태 안정성, 서로 높이가 다른 물체의 예외를 추가했다. 웹 타입 검사·린트·테스트 26개·프로덕션 빌드가 통과했다.


### 화분 주변 소품과 바닥 액자 보정

화분과 겹치던 작은 원목 의자를 책/상판/다리가 함께 움직이는 그룹으로 만들었다. 바닥 액자·오토만·작은 의자는 화분 전체의 월드 경계상자와 서로의 경계를 검사해 0.14 간격을 두고 빈 위치로 밀어낸다. 방 오른쪽의 허용 범위 안에서만 이동하며, 초기 배치에서 바닥 소품 충돌 수는 0이다. 실제 개별 메시보다 보수적인 경계상자로 잎 주변에도 여유를 둔다.

바닥 액자는 기존 고정 중심 높이 .74에서 계산 없이 기울여 아래쪽이 떠 있었다. 현재는 회전 후 실제 메시 경계의 최저점을 바닥 + .003에 맞춘다. 독립된 액자가 어느 각도에서도 설 수 있도록 뒤쪽 경첩과 두 원목 받침대를 추가하고, 기울어진 다리 끝의 반지름도 바닥 접점 계산에 포함했다. 화분과 작은 의자도 최저점을 바닥에 맞추고, 러그와 겹치는 오토만은 러그 표면에 맞췄다. 러그를 숨기거나 다시 펼치면 높이를 다시 계산한다.

Chrome 1507×1191에서 확대·옆면 회전으로 화분/의자 분리와 액자 뒤 받침/바닥 접촉을 확인했다. frameBottom=.0030, floorCollisions=0을 확인했고, 러그 표시를 끄면 오토만 바닥이 .0855→.0030, 다시 켜면 .0855로 복원된다. 375×812에서도 전체 공간 및 같은 접점/충돌 값을 확인했다. 회전·이동·비균일 크기의 상위 그룹 안에서 기울어진 물체를 바닥과 러그 높이에 반복 배치해 정확한 최저점과 안정성을 검증하는 테스트를 추가했다. 웹 타입 검사·린트·테스트 27개·프로덕션 빌드가 통과했다. 브라우저의 기존 HWP 확장 속성 주입으로 발생하는 hydration 경고는 별도이며, 확장 설정이나 경고 숨김 코드는 변경하지 않았다. 배포와 커밋은 하지 않았다.


### 독서 의자 공중부양 수정

읽는 의자 glTF는 회전된 메시로 구성되어 있다. 기존 빠른 경계상자의 최소 Y는 -.35647였지만 실제 정점의 최소 Y는 .04159였다. 빈 경계 공간을 바닥으로 정규화하면서 실제 다리는 약 .431 높이에 남았다. 접점 계산은 Box3.setFromObject(object, true)로 실제 변환 정점을 사용하도록 고쳤고, 의자는 전체 외형 대신 chair_oak 다리 메시를 접점 대상으로 지정했다. 상위 그룹의 월드 행렬도 먼저 갱신한다.

의자 다리가 마루와 러그에 걸쳐 있으면 바깥쪽 다리가 뜨거나 러그 안쪽으로 들어가므로, 네 다리가 러그 왼쪽의 동일한 마루 면에 닿도록 최소한으로 이동하고 뒤쪽 다리도 바닥판 안으로 맞췄다. 꾸미기에서 러그를 켜고 끌 때마다 의자 접점도 다시 계산한다. 다른 바닥 소품의 높이 진단도 정확한 정점 기준으로 갱신했다.

실제 reading-chair.glb를 로드한 회귀 테스트는 이전 배치의 큰 다리 간격을 재현하고, 네 다리를 각각 분류해 수정 후 모두 마루+.003에 닿는 것을 확인한다. 웹 테스트 28개, 타입 검사·린트·프로덕션 빌드가 통과했다. Chrome 데스크톱 책상 확대 화면과 375px 폭에서 chairBottom=.0030을 확인했고, 러그 표시를 끄고 켜도 같은 값을 유지했다. 실제 휴대전화 터치와 운영 배포는 이번에 진행하지 않았다.


### 입체 서재와 수첩 진입 경로 (2026-10-07)

PC 상단과 모바일 메뉴의 ‘내 서재’는 /study를 직접 연다. 로그인 전에도 시안 표기가 있는 입체 공간을 볼 수 있다. 기존 홈페이지의 기록 시작 CTA, 도서 등록과 개인 상세 경로는 각각의 기존 목적지를 유지한다. 입체 공간은 아직 시안 도서가 기본이며 실제 계정 책은 ‘책 추가 → 내 책 불러오기’로 표시한다.

책상 위 수첩 표지에 ‘나의 독서 수첩 / 책과 기록’을 표시하고, 실제 수첩 그룹의 클릭은 /library로 바로 이동하도록 연결했다. 책의 선택·꺼내기와 독립된 클릭 대상이며 가려진 수첩이나 카메라 드래그는 이동을 일으키지 않는다. 하단 ‘수첩 열기 · 책과 독서 기록’ 링크는 키보드와 작은 화면의 대안이다. 여러 번 누르더라도 동일 장면의 중복 페이지 이동은 방지한다. /library의 로그인 보호, HTTP-only 쿠키와 API 경계는 유지한다.

Chrome PC에서 홈 상단 버튼→입체 서재→책상 시점→실제 수첩 클릭→기존 내 서재의 로그인된 책 목록 표시를 확인했다. 375px 폭에서는 모바일 메뉴의 내 서재→입체 서재→수첩 링크→/library를 확인했다. 웹 타입 검사·린트·기존 테스트 28개·프로덕션 빌드가 통과했다. 이번 브라우저의 기존 로그인 세션을 사용했으며 로그인/로그아웃으로 사용자 세션을 변경하지 않았다. 운영 배포와 커밋은 하지 않았다.


### 클릭할 수 있는 수첩의 안내

수첩 표면에 1.1초 동안 은은한 빛줄기가 지나가고 테두리가 밝아지는 효과를 추가했다. 효과 종료 후 4.8초 쉬며, 수첩이 보이는 화면에서만 다음 효과를 시작한다. 이 사이에는 기존 요청 기반 렌더링이 쉬고, 숨겨진 탭에서는 타이머와 애니메이션을 멈춘다. 모션 감소 설정은 반복 움직임을 생략하고 정적인 테두리를 유지한다. 설정 변경·탭 복귀·그래픽 중단·장면 해제 시 타이머와 GPU 자원을 처리한다.

수첩이 실제로 보이는 위치에 ‘수첩 열기 ↗’ 링크를 투영했다. 벽이나 가구에 가려지거나 화면 밖이면 표시를 숨긴다. 실제 수첩 표면의 마우스 호버와 안내 링크의 키보드 초점에서 강조가 강해지고 손 모양 커서가 나타난다. 안내 링크, 실제 수첩, 하단 대체 링크는 모두 기존 /library로 이동한다. 링크 이동 시 다른 책의 대기 애니메이션/페이지 이동도 정리한다. 장식 메시에는 raycast와 충돌을 적용하지 않아 클릭을 가로채거나 주변 소품을 밀지 않는다.

Chrome PC 책상 확대에서 최대 밝기 상태를 캡처하고, 마우스 호버와 키보드 초점의 notebookHovered=true, 안내 효과 후 notebookPulse=0 및 책상 소품 충돌 0을 확인했다. 실제 수첩 클릭과 375px 화면의 안내 링크 Enter 입력 모두 /library로 이동했다. 웹 타입 검사·린트·테스트 28개·프로덕션 빌드가 통과했다. OS의 모션 감소 설정 변경과 실제 휴대전화 터치는 직접 실행하지 않았다. 기존 HWP 확장에 의한 hydration 경고는 별도이다. 운영 배포와 커밋은 하지 않았다.
